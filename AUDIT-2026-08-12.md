# Mini Games Platform Comprehensive Audit

**Date:** 2026-08-12  
**Scope:** All 13 games, bot behavior, multiplayer fairness, reconnects, responsive UX, accessibility, lifecycle, infrastructure, and domain migration  
**Live baseline audited:** `https://api.gary-yong.com/play/`  
**New canonical hostname:** `https://play.gary-yong.com/`

## Executive assessment

The platform's lightweight plugin architecture is worth preserving, but the March 2026 status overstated reconnect and tutorial completeness. The live product is functional at the happy-path level, yet lacks the authority, restore-contract, test, lifecycle, and design rigor needed for fair reaction games and reliable mobile/desktop play.

The remediation strategy is a dependency-ordered campaign rather than a cosmetic patch:

1. Test harness and deterministic fixtures
2. Reconnect identity and Socket.IO validation
3. Room/game/timer lifecycle
4. Per-game authority and restore contracts
5. Bot scheduling and difficulty realism
6. Multiplayer latency and input fairness
7. Safe client lifecycle and rendering
8. All-game instruction system
9. Responsive Arcade Field Guide visual system
10. Exact-candidate QA, domain cutover, and production verification

## Critical and high-risk systemic findings

### A-01: Reconnect identity takeover — Critical

**Evidence:** `server/server.js:68-73`, `server/rooms.js:54-81`, `public/js/main.js:54-74`.

A room code plus case-insensitive display name is sufficient to inherit a disconnected player's score, socket-linked state, and host authority during the grace period.

**Required fix:** server-issued stable player ID and cryptographically random reconnect token; store only the token hash; require and rotate the token on successful rejoin; display names are never identity.

**Acceptance:** missing, wrong, stale, cross-player, and replayed tokens fail without mutating the room; the legitimate token restores exactly one player.

### A-02: Client-authoritative Type Racer timing — Critical

**Evidence:** `server/games/type-racer.js:155-174` trusts positive `data.elapsed`.

A probe produced 228,000 WPM and 228,050 points by submitting an arbitrarily small elapsed value.

**Required fix:** score from server monotonic receipt time; require exact authoritative sentence; preserve progress only as presentation/anti-anomaly evidence; reject duplicate/stale round actions.

### A-03: Reconnect serializers are contract-incomplete or leak hidden state — Critical

Examples:

- Tap Frenzy reads nonexistent `roundStart`, `leaderboard`, and `roundResults`, and assumes 10 seconds instead of configured 8 seconds.
- Word Scramble does not persist the scrambled text and assumes 25 seconds instead of its normal contract.
- Number Guess reads `roundStart` despite not storing it and assumes 60 seconds rather than 45 seconds.
- Geography Quiz reads `q.question` instead of `q.q` and uses a mismatched duration.
- Emoji Match returns the complete hidden board during active play.
- Several result snapshots return fields never persisted.

**Required fix:** explicit public-state serializer per game and phase, validated against the client contract; no undefined fields and no hidden answer/card/number leakage.

### A-04: Socket payload validation and crash containment — High

Socket envelopes are destructured without a shared plain-object/schema boundary. Multiple games dereference null or permissively parse numeric prefixes. Many rejection paths are silent.

**Required fix:** strict event contracts, finite/ranged values, byte limits, enumerations, typed acknowledgements, and guarded dispatch that logs safe metadata without crashing the process.

### A-05: Room and timer lifecycle — High

Rooms are deleted based on `createdAt` after two hours, even if active. Timer ownership is spread across game-specific arrays, bot timers, grace timers, and unguarded delayed initialization. Stale callbacks can cross lobby/game/round boundaries.

**Required fix:** `lastActivityAt`, centralized destruction, room epoch/game instance/round guards, one timer registry, and zero retained timers/listeners after teardown.

### A-06: Hard-coded socket-ID migration — High

`rooms.js` migrates only a named subset of Map/Set fields. New or nested socket-linked state can retain the old ID, causing duplicate actions, stalled turns, or lost progress.

**Required fix:** one tested recursive identity migration primitive plus explicit exclusions for immutable data.

### A-07: Reaction-game network bias — High

Reaction Race ranks server receipt time. Transport latency therefore contributes directly to the displayed reaction time and winner order.

**Required casual-game fairness model:**

- Server monotonic go/receive timestamps
- Round ID and unguessable round token
- Periodic acknowledged RTT samples
- Conservative bounded compensation using the minimum recent RTT divided by two
- Compensation ceiling such as 75 ms
- Raw, compensated, adjusted, and uncertainty values retained for audit
- Tie/shared points when uncertainty bands overlap
- No client timestamps as authority

This reduces ordinary network bias but cannot prove when a human saw a browser frame. Strong competitive integrity would require controlled clients or regional/referee infrastructure.

### A-08: High-frequency and duplicate actions — High

Tap Frenzy accepts every tap while active with no plausible human burst/sustained ceiling. Several start/finish/answer paths lack action IDs or same-tick duplicate guards.

**Required fix:** per-player/round token buckets, typed action IDs, idempotent duplicates, changed-payload conflict handling, and stale-round rejection.

### A-09: Disconnected-player handling is inconsistent — High

Some games exclude disconnected players from completion checks; others wait through the full timeout. Emoji Match can assign turns to an away player and has no turn deadline. Type Racer includes disconnected humans in all-done checks.

**Required fix:** one active-player predicate, disconnect-aware completion, bounded turn deadlines, and deterministic host migration.

### A-10: Client lifecycle and safe rendering — High

Game clients have inconsistent cleanup; transitions can retain intervals, timeouts, requestAnimationFrame callbacks, and global queries. Core code removes all listeners for shared event names rather than its own callbacks. Player-supplied names enter several `innerHTML` templates.

**Required fix:** explicit mount/destroy lifecycle, owned listener identities, scoped queries, buffered reconnect snapshot until the client module is ready, and DOM/textContent rendering for untrusted data.

## Per-game audit summary

### Reaction Race

- Network RTT influences result ordering.
- False starts currently have no meaningful competitive penalty and still allow a normal second chance.
- Result reconnect field names differ from normal result events.
- Add round token, false-start rule, monotonic timing, bounded compensation, uncertainty ties, and result-contract parity.

### Trivia Blitz

- Basic input type validation exists, but option range and complete result restore need strict contracts.
- Receipt timing is authoritative but network-biased for close answers.
- Bot correctness/delay distributions need seeded statistical tests.

### Tap Frenzy

- No input-rate ceiling; scripted taps can dominate.
- Restore contract uses fields and timing that do not exist.
- Add token-bucket limits, live count serialization, exact remaining duration, and disconnect-aware ranking.

### Word Scramble

- Scrambled text is emitted but not persisted for restore.
- Restore field names and duration disagree with live events.
- Shuffle retry is only safe because the current pool contains longer words.
- Persist public prompt, make shuffle total for arbitrary input, and use one duration constant.

### Emoji Match

- Reconnect leaks the full hidden board.
- Bot passive-learning section is empty, so bots do not learn from observed human flips.
- A disconnected turn can stall play.
- Serialize only matched/currently visible cards, add turn deadline, and expose fair observation events to bot memory.

### Math Blitz

- `parseInt` accepts numeric prefixes.
- Answer and restore contracts need finite-integer validation and exact timer fields.
- Disconnected players can delay early completion.
- Keep server receipt scoring and seeded problem generation tests.

### Simon Says

- Eliminated players lack a useful spectator/practice state.
- Restore phases/fields differ from normal events.
- Timer callbacks need game-instance guards.
- Add spectator presentation without allowing authoritative input.

### Color Clash

- Platform design must not use purple/blue, but this game may retain semantic game colours only where required by its Stroop mechanic.
- Completion includes disconnected players.
- Restore result state references data not persistently modeled.
- Validate enum options and preserve visible semantic labels beyond colour alone.

### Type Racer

- Critical client elapsed exploit.
- Bots are always 100% accurate.
- Disconnected players prevent early completion.
- Restore forces at least five seconds even when less remains.
- Move all timing authority server-side, model realistic bot mistakes, and return exact remaining time.

### Color Picker

- `parseInt(value) || 0` silently coerces malformed input.
- Completion includes disconnected players.
- Restore result fields are not persistently modeled.
- Require finite integer RGB channels from 0–255 and explicit result serialization.

### Geography Quiz

- Restore reads the wrong question property and mismatched duration.
- Bot polling can schedule duplicate delayed moves unless pending actions are tracked.
- Add exact question serializer, strict choice range, and one pending bot action per round.

### Hangman

- Bot full-word guesses are generated by naive blank filling and can be nonsense.
- Restore references result fields not consistently persisted.
- Validate one Unicode-safe A–Z letter or bounded word; add dictionary-pattern bot lookup.

### Number Guess

- Multiple players can continue solving and scoring after the first winner unless the round closes atomically.
- Restore timestamp/duration is invalid.
- `parseInt` accepts numeric prefixes.
- Mark the round solved atomically on first accepted answer and use strict integer validation.

## Bot architecture findings

The platform has two patterns: nine inline polling bots in `bots.js` and four module-level `getBotMove()` implementations. The generic dispatcher polls every two seconds and can queue more than one delayed action before the first fires.

**Required behavior:**

- At most one pending action per bot, game instance, and round
- Delayed action revalidates game instance, round, phase, membership, acted state, and legal action
- Cleanup cancels all pending bot work
- Difficulty simulations verify configured accuracy/speed distributions over seeded runs
- Type Racer bots include difficulty-based mistakes and retries rather than perfect final text
- Emoji Match bots learn only from publicly revealed information

## UX and design audit

### Current-state diagnosis

- Generic emoji controller logo
- Navy/purple gradient and rounded-card visual grammar
- Default system font
- 480 px desktop column with large unused margins
- Flat information hierarchy and repetitive game tiles
- Weak keyboard semantics: game cards are clickable divs
- No reduced-motion mode
- No complete focus-visible system
- Only three real game tutorials
- Generic countdown presented as instruction for ten games
- Sparse result celebration and abrupt state transitions

### Approved design direction: Arcade Field Guide

**Palette:** warm near-black ink, parchment, vermilion, marigold, moss, muted clay. No purple or blue in platform chrome.

**Language:** editorial display typography, monospaced scoreboard details, tactile printed-rule-card motifs, asymmetric game tiles, clear field labels, restrained texture, and purposeful state motion.

**Responsive behavior:**

- Desktop uses a wider two-zone composition for room/player context and game library
- Mobile preserves one-handed primary actions, safe-area padding, and 44 px targets
- No horizontal overflow at 320, 390, 768, 1024, and 1440 px
- Active game geometry is measured, not inferred from screenshots

**Instruction contract for every game:** objective, control, scoring, round/timeout rule, false-start/mistake rule where relevant, and a persistent help control. First play may show a short demonstration, but returning players can skip it without delaying server authority.

**Motion contract:** room entry, game selection, round transition, score increment, correct/incorrect feedback, podium reveal, and restrained winner celebration. `prefers-reduced-motion: reduce` provides equivalent information with no required animation.
