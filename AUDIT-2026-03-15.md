# Mini Games Platform — Comprehensive Audit
**Date:** 2026-03-15
**Auditor:** Dr. Molt (Senior Engineering Advisor)
**Scope:** All 13 games — Bot AI Quality + User Experience

---

## 1. Executive Summary

The Mini Games platform has a solid foundation — clean plugin architecture, good Socket.IO patterns, and thoughtful reconnection handling. However, the audit surfaces one **critical systemic issue** and several medium-priority improvements:

### The Big Finding: 4 Games Have Dead Bots 🔴
**color-picker, geography-quiz, hangman, and number-guess** all define `getBotMove()` methods that are **never called**. The `scheduleBotActions()` switch in `bots.js` has no cases for these games. Bots join but sit completely idle — they never guess, never answer, never submit. This is the #1 priority fix.

### Bot Quality Overall: Mixed
- 9 games have working bot implementations with reasonable difficulty differentiation
- The original 9 use a polling-loop pattern with game-specific code in `bots.js`
- The newer 4 games tried to use a cleaner `getBotMove()` return-an-action pattern, but nobody wired it into the bot scheduler
- Bot behavior ranges from excellent (math-blitz with wrong-answer retry) to simplistic (type-racer with 100% accuracy)

### UX Quality Overall: Good with Gaps
- Client code is well-structured with clear phase handling
- Most games have good visual feedback and timers
- **Major gap:** Only 1 of 13 games (type-racer) implements `getReconnectState()` — reconnecting players get blank screens in 12 games
- No game rules/instructions are shown before play
- Some inconsistencies in maxPlayers limits

## 3. Top 10 Highest-Impact Improvements

### 1. 🔴 Wire up getBotMove() for 4 orphaned games — **Effort: S** ⏱ ~1-2h
**Games:** color-picker, geography-quiz, hangman, number-guess
**Impact:** Critical — these games are unplayable with bots (bots join but never act)
**Fix:** Add a generic `getBotMove()` polling loop in `bots.js` and add switch cases, OR add a unified `startGenericBot()` that calls `game.getBotMove()` on a timer and dispatches the returned event. The game modules already return `{ event, data, delayMs }` — just need the dispatcher.

### 2. 🔴 Add getReconnectState() to all 12 missing games — **Effort: M** ⏱ ~3-4h
**Games:** All except type-racer
**Impact:** High — any disconnect during gameplay = blank screen. Mobile players (switching apps, losing signal) are hit hardest.
**Fix:** Each game needs a `getReconnectState(room)` method returning enough state for the client to render the current phase.

### 3. 🟡 Expand question pools for trivia-blitz and geography-quiz — **Effort: M** ⏱ ~2-3h
**Games:** trivia-blitz (20 questions), geography-quiz (45 questions)
**Impact:** Medium-high — repeat play gets stale fast. Trivia only has 20 questions for 7-round games = guaranteed repeats after 3 plays.
**Fix:** Expand to 60+ questions each. Consider external question APIs for infinite variety.

### 4. 🟡 Add game rules/instructions — **Effort: S** ⏱ ~2h
**Games:** All 13
**Impact:** Medium — new players don't know what to do. The game descriptions are in the lobby game picker but not shown during gameplay.
**Fix:** Add a brief "How to play" tooltip or banner at the start of each game's first round. Client-side only change.

### 5. 🟡 Make type-racer bots less perfect — **Effort: S** ⏱ ~1h
**Game:** type-racer
**Impact:** Medium — hard bots with 100% accuracy and fast WPM are impossible to beat and feel robotic.
**Fix:** Add occasional typo simulation, especially for easy/medium bots. Maybe 95% accuracy for hard, 85% for medium, 70% for easy.

### 6. 🟡 Fix emoji-match bot passive learning — **Effort: S** ⏱ ~1h
**Game:** emoji-match
**Impact:** Medium — the bot memory system has a section that says "learn from other players' flips" but the code is empty. Bots don't learn from cards flipped by other players, making them weaker than intended.
**Fix:** When the server broadcasts a `flip` event, update the bot's memory map with the revealed emoji.

### 7. 🟡 Add engagement for eliminated Simon Says players — **Effort: S** ⏱ ~1h
**Game:** simon-says
**Impact:** Medium — eliminated players stare at a static screen. In a 12-round game, early elimination means minutes of nothing.
**Fix:** Show the sequence being played to eliminated players as spectators. Maybe show a "practice mode" where they can tap along without affecting the game.

### 8. 🟡 Normalize maxPlayers across games — **Effort: S** ⏱ ~30min
**Games:** geography-quiz (max 8), hangman (max 16), others (max 20)
**Impact:** Low-medium — confusing when rooms can't play certain games because they have too many players.
**Fix:** Standardize to 20 for all, or add server-side validation with clear error messages.

### 9. 🟡 Duplicate trivia questions across trivia-blitz and geography-quiz — **Effort: S** ⏱ ~30min
**Games:** trivia-blitz, geography-quiz
**Impact:** Low — "Capital of Australia" appears in both games. "Longest river" appears in both.
**Fix:** Deduplicate. Geography-specific questions stay in geography-quiz; general knowledge stays in trivia-blitz.

### 10. 🟢 Add score animation/feedback on game:end — **Effort: S** ⏱ ~1h
**Games:** All 13
**Impact:** Low-medium — game endings feel abrupt. No celebration, no confetti, no "you came in 2nd!" callout.
**Fix:** Client-side: add winner announcement animation, podium display, maybe confetti for 1st place.

## 4. Bot Architecture Observations

### Current Architecture: Two Incompatible Patterns
The codebase has evolved into two bot patterns that don't talk to each other:

**Pattern A — Inline Polling (original 9 games):**
Each game has a dedicated `start<Game>Bot()` function in `bots.js` that creates a polling interval. The function contains all game-specific logic inline. This works but creates tight coupling and lots of code in `bots.js`.

**Pattern B — getBotMove() Return (newer 4 games):**
The game module defines `getBotMove(room, bot)` that returns `{ event, data, delayMs }`. This is cleaner and more modular. **But nothing calls it.**

### Recommended Fix: Unified Bot Dispatcher
Add a generic bot dispatcher in `bots.js`:

```javascript
function startGenericBot(room, io, botId, bot, sock) {
  const poll = setInterval(() => {
    const gs = room.gameState;
    if (!gs || gs.phase === 'finished') { clearInterval(poll); return; }
    
    const game = room.currentGame;
    if (!game || !game.getBotMove) return;
    
    const move = game.getBotMove(room, { ...bot, id: botId });
    if (!move) return;
    
    if (move.delayMs) {
      const t = setTimeout(() => {
        game.onEvent(room, sock, move.event, move.data, io);
      }, move.delayMs);
      addTimer(room, t);
    } else {
      game.onEvent(room, sock, move.event, move.data, io);
    }
  }, 2000);
  addTimer(room, poll);
}
```

Then in `scheduleBotActions`, add a default case:
```javascript
default:
  if (game.getBotMove) startGenericBot(room, io, botId, bot, sock);
  break;
```

Over time, migrate the original 9 games from inline Pattern A to the cleaner Pattern B.

**Verdict:** All "cheating" is necessary for bots to function. The difficulty system (accuracy chance, timing) adequately compensates. No unfair advantages detected.

### Timer Management
Each game creates its own timer arrays (`room._rrTimers`, `room._tfTimers`, etc.). `clearBotTimers()` in bots.js only clears `room._botTimers`. Game-specific timers are cleaned up by each game's `cleanup()` method. This is fine but fragile — if `cleanup()` is forgotten, timers leak.

## 6. Tech Debt Cross-Reference

The following should be added to TECH_DEBT.md if not already tracked:

### New Items to Add
1. **Two incompatible bot patterns** — unify on `getBotMove()` return pattern (see Section 4)
2. **Missing getReconnectState()** — 12 of 13 games lack reconnection support. Mobile players get blank screens.
3. **Per-game timer arrays are fragile** — each game manages its own timer cleanup. A missed cleanup = leaked intervals. Consider a unified timer manager on the room object.
4. **Hardcoded question pools** — trivia-blitz (20 questions) and geography-quiz (45 questions) are static arrays. Consider loading from JSON files or an API for easier expansion.
5. **No game-level input validation** — most games trust client data (e.g., color-clash accepts any string as `choice`, not just valid colors). Server should validate against `gs.options`.
6. **Geography-quiz has lower maxPlayers (8)** than other games (20) — no clear reason. Causes confusing "can't start game" errors in large rooms.
7. **Word scramble's scramble() can theoretically infinite-loop** if the word is 1-2 chars (all permutations might equal the original). Current word list is safe but the function isn't.
8. **No bot action for hangman word-guessing** — hard bots attempt word guesses but with a naive approach (fill blanks with most-common letters). The resulting "word" is often nonsense. Should use a dictionary lookup instead.

### Already Tracked (verify still relevant)
- Mobile touch handling (fixed in tap-frenzy, verify others)
- Socket.IO reconnection grace period (implemented in rooms.js ✅)
- Double-fire prevention on round results (implemented across games ✅)

## Appendix A: Detailed Per-Game Notes

### Reaction Race
- **Server:** Clean 5-round structure. Early tap handling is good (separate set for early tappers).
- **Client:** Simple and effective. Touch targets are fine (full-screen zone).
- **Bot:** Speed ranges well-differentiated: Easy 400-900ms, Medium 220-500ms, Hard 130-300ms. Realistic.
- **Edge cases:** Early tappers can still tap on GO — by design, gives second chance. Good.

### Trivia Blitz
- **Server:** Round timer properly tracks and cancels. Active player check excludes disconnected players.
- **Client:** Timer bar, option highlighting, results display all good.
- **Bot:** Accuracy differentiation (40%/70%/92%) + speed differentiation. Good.
- **Issue:** Only 20 questions. 7 rounds per game = stale after 3 plays.

### Tap Frenzy
- **Server:** Live tick broadcast every 500ms. Point table rewards top 3.
- **Client:** Touch/click dual handling properly prevents double-fire on mobile. Live leaderboard.
- **Bot:** TPS ranges: Easy 3-5, Medium 6-9, Hard 10-15. Realistic human-like TPS.
- **Minor:** No random variance in bot tap timing — perfectly uniform intervals could feel robotic.

### Word Scramble
- **Server:** First-to-solve ranking with diminishing points (150/100/75/50/25). Timer-based round.
- **Client:** Auto-capitalize, shake on wrong answer, countdown display.
- **Bot:** Solve probability (45%/75%/95%) + delay (7-13s/3.5-7s/1.5-4s). Good spread.
- **Note:** Bot reads answer from `gs.words[]` — necessary, not exploitable by human players.

### Emoji Match
- **Server:** Turn-based with match=same-player-continues. Board sizes increase (12/16/20). Locking prevents triple-flip.
- **Client:** Card flip animations, match highlighting, turn indicator.
- **Bot:** Memory system with difficulty-based recall chance (20%/55%/85%). However:
  - **Bug:** Passive observation code block (lines 141-148 in bots.js) is empty — bots only remember cards they flip themselves, not cards flipped by other players.
  - This makes bots significantly weaker than a human who watches all flips.
- **UX Issue:** Watching other players' turns with no interaction can feel slow, especially with many players.

### Math Blitz
- **Server:** Difficulty scales within the game (Easy → Expert over 8 rounds). Wrong answers don't lock you out — can retry. Speed + first-solver bonuses.
- **Client:** RAF-based timer, difficulty level indicator, shake on wrong answer. Well polished.
- **Bot:** Best bot implementation — wrong answer attempts followed by possible retry. Accuracy + speed + retry probability all scale with difficulty. Very human-like.

### Simon Says
- **Server:** Elimination-based. 12-round max. Full sequence generated upfront. Points scale with round number. Survivors get 200pt bonus.
- **Client:** Four-color pad with lit/pressed states. Shows progress (entered/needed). Eliminated state display.
- **Bot:** Accuracy degrades with sequence length (baseAccuracy - round*0.03). Speed per button press scales with difficulty. Good.
- **UX Issue:** Eliminated players have nothing to do. No spectator mode for watching the sequence being played.

### Color Clash
- **Server:** Stroop effect with time pressure that increases each round (5000ms → 1500ms over 10 rounds). Streak system awards bonus points.
- **Client:** Large color buttons, timer bar, streak display. Inline CSS (could be in stylesheet).
- **Bot:** Smart wrong-answer behavior — picks the WORD (the classic Stroop error) when incorrect. Accuracy: 50%/75%/93%. Good psychology.
- **Minor:** Inline `<style>` in client — should be in main CSS file.

### Type Racer
- **Server:** WPM × accuracy scoring. Position bonuses (50/30/10). getReconnectState() implemented (only game with this!).
- **Client:** Character-by-character highlighting, progress bars for all players, robust reconnection handling. Most polished client.
- **Bot:** Speed-only differentiation (18-25s/10-17s/3-9s). **Always 100% accuracy.** Not realistic — humans make typos, especially when rushing.
- **Fix needed:** Add typo rate scaling with difficulty.

### Color Picker
- **Server:** RGB slider matching with perceptually-weighted color distance. Score = accuracy² × speed factor. Well-designed scoring.
- **Client:** Beautiful dual-swatch UI with real-time preview, hex display, accuracy feedback. Most visually polished game.
- **Bot:** `getBotMove()` returns a color guess with spread: Easy ±90, Medium ±35, Hard ±12. Good difficulty scaling.
- **🔴 CRITICAL:** `getBotMove()` is **never called** — no entry in `scheduleBotActions()` switch statement.

### Geography Quiz
- **Server:** Identical structure to trivia-blitz but with geographic focus. 1000 base + 500 speed bonus scoring. Shows who has answered.
- **Client:** A/B/C/D labels, answered-player indicators, running scoreboard. Clean.
- **Bot:** `getBotMove()` uses elapsed-time check as delay (returns null if not enough time has passed). Accuracy: 40%/65%/90%.
- **🔴 CRITICAL:** `getBotMove()` is **never called** — no entry in `scheduleBotActions()` switch statement.
- **Note:** maxPlayers is 8 (vs 20 for most games) — no technical reason for this limit.

### Hangman
- **Server:** Collaborative/competitive hybrid — all players guess letters (shared hangman), race to guess the word. Points for correct letters + word solve bonus with time factor.
- **Client:** Beautiful SVG gallows with progressive body parts and X-eyes on death. Full QWERTY keyboard. Word-guess input. Most visually impressive client.
- **Bot:** `getBotMove()` uses letter frequency ordering (ETAOIN...). Hard bots attempt word guesses when >60% revealed with ≤2 blanks. Medium uses top-10 frequency. Easy is random.
  - **Issue:** Word completion attempts fill blanks with common letters sequentially — produces nonsense words (e.g., "ALGORET_M" → "ALGORETMM"). Should use dictionary matching instead.
- **🔴 CRITICAL:** `getBotMove()` is **never called** — no entry in `scheduleBotActions()` switch statement.

### Number Guess
- **Server:** Hot/cold with shared hint log. Range increases with rounds (1-100 → 1-500). First solver gets bonus + fewer guesses = more bonus.
- **Client:** Clean guess log with directional arrows, feedback display, timer. Well done.
- **Bot:** `getBotMove()` implements binary search (hard), noisy binary search (medium), random (easy). Uses OWN guesses to narrow range.
  - **Issue:** Bot only reads hints from its own guesses (`entry.playerName === bot.name`). Misses useful higher/lower hints from other players. A human would use ALL hints.
- **🔴 CRITICAL:** `getBotMove()` is **never called** — no entry in `scheduleBotActions()` switch statement.
